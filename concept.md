# BK-PHENIX — концепция (по чату «Приложение для позиционирования»)

## Что это
Лёгкое Android-приложение для достоверного позиционирования телефона (проблема — глушение/подмена GNSS в Москве). Главная ценность — не маршрут, а **достоверность координаты**: сверка всех источников, отсев ложных данных, понятная погрешность.
Название: **BK-PHENIX** (BK — инициалы Бориса Кутырина). Модули: BK-PHENIX Navigator / Core / GNSS Integrity / Diagnostics. Пакет `ru.bkphenix`.

## Цели и принципы
- Использовать все доступные источники: GPS, ГЛОНАСС, Galileo, BeiDou, QZSS/SBAS, A-GPS, сотовые/Wi-Fi, гироскоп, акселерометр, магнитометр, барометр.
- **Компаратор**: сравнение источников между собой, отсечение неверных, итоговая погрешность.
- **Контроль целостности «по Хэммингу»**: проверка в процессе вычисления (чётность/синдромы на уровне данных навигационного сообщения GPS subframe, консистентность решения). Цель — выявлять не «враньё», а **блокировку, скачок или подмену координат** (jamming/spoofing).
- **Human Anchor — приоритет №1**: начальную позицию указывает/подтверждает человек; код — второй проверяющий. Нет якоря → предупреждение. Явная ошибка человека → сообщить, но не переписывать якорь. Проработать ручной и автоматический пути.
- Оценка и визуализация **накопленной ошибки (drift)** и её коррекция (dead reckoning при пропадании GNSS).
- Приведение данных разных спутниковых систем к **единому формату записи** (UnifiedGnssObservation, единое время).
- Показ состояния и названия GNSS-модуля (чип), числа и типов спутников.
- Интерфейс на русском, акцент на юзабилити. Карты — только бесплатные, хранятся локально (офлайн). Без голосовых подсказок. Replay в релизе не будет.

## Режимы
Определение местоположения; координата с погрешностью; запись трека; навигация (позже); пешком / авто / «без привязки» (указатель направления/расстояния на точку без улиц).

## Архитектура ядра (из чата, Kotlin)
PositionObservation / PositionSource → PhenixComparator / PositionComparator → ComparisonResult (+IntegrityState) → IntegrityEngine, HammingIntegrityEngine (GpsSubframe) → AnchorManager/HumanAnchor (AnchorStatus: NO_ANCHOR, HUMAN_ANCHOR, ANCHOR_CONFLICT) → PhenixCore/PhenixSolution. Плюс GnssReceiverInfo/State, SatelliteStatus, GnssConstellation, GnssBand, EcefCoordinate, GnssTime.
Принцип: ни один источник не абсолютен, кроме подтверждённого якоря; все данные идут через единый контур доверия.

## Текущее состояние
Борис начал в Android Studio (проект `ru.bkphenix`, minSdk 24, targetSdk 37), затем перешёл в IntelliJ IDEA: консольный Kotlin-проект `BK-PHENIX-Core` (JDK 26, Kotlin 2.4 — была ошибка экспериментальной версии). Протестированы компаратор и Human Anchor; следующий шаг в чате — тест ANCHOR_CONFLICT при сдвиге GNSS на 500 м. Код вставлялся руками по шагам.

## Продуктовая линейка (после прототипа)
Платная полная версия; Lite («одна кнопка», «dumm»); Pro с отключением модулей (якорь, части компаратора) ради максимальной точности. Коммерческие карты, логирование — только после рабочего прототипа.

## Предлагаемый MVP
**Стек:** Kotlin, Android (minSdk 26+), Gradle KTS, Jetpack Compose (UI на русском), модуль `core` на чистом Kotlin/JVM (тестируемо без телефона, JUnit), Android API: LocationManager (GNSS + network), GnssStatus, GnssMeasurementsEvent, GnssNavigationMessage, SensorManager; карты — MapLibre Native + офлайн OSM-тайлы (MBTiles/PMTiles); Room для треков; трек экспорт GPX.
**Этапы:**
0. Репозиторий, структура `:core` + `:app`, перенос текущих классов, CI-сборка APK.
1. Core: единая модель наблюдений, компаратор, IntegrityEngine (скачки, рассогласование, C/N0-аномалии, признаки spoofing), Human Anchor с конфликтами, оценка ошибки/дрейфа; юнит-тесты со сценариями (глушение, подмена, сдвиг 500 м).
2. App: сбор данных со всех провайдеров и датчиков, экран «Координата» (точность, статус целостности, якорь), экран «Спутники» (созвездия, чип GNSS, состояние).
3. Hamming/raw: проверка чётности навигационных сообщений GPS (где устройство отдаёт), сравнение raw-измерений.
4. Офлайн-карта, установка/подтверждение якоря на карте, запись трека, визуализация накопленной ошибки.
5. Режим «без привязки» (стрелка/расстояние к точке); навигация по улицам — после.
